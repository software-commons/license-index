## Protected review and commissioning boundary

The delta stages exact root-owned, hash-pinned assets into a root-owned review directory after the issuer validates its protected ancestor chain. An issuer-side preflight validates the launcher, verifier, pinned interpreter, exact base/head and archive digest, then checks them again after reviewer execution; failed or changed preflight prevents any verdict or App check. The reviewer runs an isolated, environment-cleared command and still must independently inspect snapshot/source bytes and evaluate the recorded counts. The existing nonce-bound `history-proof 0` binds the archive; neither that proof nor preflight alone is scientific or technical approval.

Before use, an eligible independent reviewer must review the full delta, source assets, packaging and tests. The proposed format dispatcher applies a new 8 MiB manifest limit and 100,000-object limit to v1 as well as v2; the prior v56 loader did not enforce those separate bounds. The existing v1 sample passed, but this does not establish compatibility for every previously accepted v1 archive. An isolated trial must exercise v1 compatibility within these bounds, valid v2, missing/stale/wrong-source checks, hostile archives and path substitution, issuer-owned staging, matching preflight/reviewer inodes and traces, required CI, and protected queue behavior. A separately pinned runtime must be staged and checked against the reviewed artifacts. No production runtime, key, App permission, branch rule, or Language Index configuration is changed by adding this artifact. Do not deploy an unreviewed or uncommissioned package.
