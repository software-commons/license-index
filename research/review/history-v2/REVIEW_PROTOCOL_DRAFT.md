# Scratch v2 reviewer protocol draft

Preserve the existing v1 prompt, history receipt and nonce-bound trace proof for v1 archives that pass the proposed dispatcher. The dispatcher adds an 8 MiB manifest limit and 100,000-object limit that the prior v56 loader did not separately enforce; complete compatibility with every previously accepted v1 archive has not been established. For v2, bind the exact same `review_history_sha256` and per-archive `history-proof 0` formula. The new protected prompt must identify the exact `license-index-history-v2` format and staged, separately pinned issuer-owned verifier; require the reviewer to inspect the archive as data, never execute candidate content, independently examine every coverage snapshot and the source manifests at frozen commits and compare recorded counts, and return inconclusive if any verification or inspection cannot be completed. The proof demonstrates exact archive inspection; it is not technical or scientific approval.

For the v2 process, invoke Python in isolated mode (`-I`) on the issuer-owned launcher, loading only the digest-pinned issuer-owned single-file verifier, with bounded address space, CPU and wall time. Bind repository, base, head, archive digest and the inspection token from `review-input.json`. The verifier returns the unchanged nonce-bound `history-proof 0` format only after graph, object, snapshot, canonical framing, completeness and limits pass. The runner must record command execution and successful output in the native reviewer trace; the existing trace validator should recognize the existing label and formula. The reviewer must still open and evaluate snapshot/input bytes and candidate patch independently. Never treat verifier success as approval.

This document is a proposal only. The protected prompt, loader, verifier package, staging ownership, trace integration and backwards-compatible v1 path have not been changed or commissioned. A real restricted reviewer sandbox execution and adversarial tests are required before deployment.
