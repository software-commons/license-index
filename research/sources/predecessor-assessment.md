# Licensing infrastructure and source authority

Assessment date: 2026-11-22. The sources below were consulted for catalog and implementation decisions. This record identifies the source and scope of each observation. Formal qualification and source-byte acquisition are tracked separately.

## SPDX publication contract

The SPDX License List and both upstream release pages identified **3.29.0**, dated **2026-09-16**, as the latest stable list at the time of assessment. The list-source repository release points to `b1dbeb5c8bca21af860a90e187f71d60b84a7a40`. The generated-data release points to `31ba1a50e5397e00a304dbadc76531740e89ee48`. Those are separate source revisions. A legal instrument's own edition, the SPDX specification version, an SPDX identifier or expression, and a Software Commons release are separate fields. [License List](https://spdx.org/licenses/), [XML release](https://github.com/spdx/license-list-XML/releases/tag/v3.29.0), [generated-data release](https://github.com/spdx/license-list-data/releases/tag/v3.29.0).

The generated-data commit publishes summary manifests in `json/licenses.json` and `json/exceptions.json`, detail JSON by identifier, simple text, matching templates, and other serializations. The summary manifests account for 740 license-list entries, including 32 deprecated identifiers, and 86 exception entries, including one deprecated identifier. Count deprecation independently from current law, publisher edition status, historical alias relationships, and Software Commons acceptance. Source entries may represent related instruments such as a public-domain mark. [License manifest](https://github.com/spdx/license-list-data/blob/31ba1a50e5397e00a304dbadc76531740e89ee48/json/licenses.json), [exception manifest](https://github.com/spdx/license-list-data/blob/31ba1a50e5397e00a304dbadc76531740e89ee48/json/exceptions.json), [SPDX fields](https://github.com/spdx/license-list-XML/blob/main/DOCS/license-fields.md).

Ingest the supported, pinned generated formats. Pin the upstream archive digest and immutable paths to exact blobs. Reconciliation can use a small, separately versioned XML reader if a necessary field is missing from the published JSON. Upstream designates XML an internal format with potential backwards-incompatible changes. Generated release tags can also differ at the patch level because of data formatting changes. [Generated formats and tags](https://github.com/spdx/license-list-data/blob/v3.29.0/README.md), [programmatic access](https://github.com/spdx/license-list-data/blob/v3.29.0/accessingLicenses.md), [XML source guidance](https://github.com/spdx/license-list-XML/blob/b1dbeb5c8bca21af860a90e187f71d60b84a7a40/README.md).

Treat simple text, official header, and matching template as separate representations. Preserve the byte digest of the file consumed. A publisher's English legal code and a generated SPDX text file can use different line wrapping or punctuation. Preserve their distinct provenance and use separate records for any intentionally rendered output. SPDX's matching guidelines address identification. For example, MIT's replaceable matching spans include both the copyright line and several ordinary phrases, so the template's grammar is unsafe as a general document generator. Install only documented, source-bound output recipes with explicit placeholder validation and a baseline byte digest. [Normative matching guidelines](https://spdx.github.io/spdx-spec/v3.0.1/annexes/license-matching-guidelines-and-templates/), [pinned MIT detail](https://github.com/spdx/license-list-data/blob/31ba1a50e5397e00a304dbadc76531740e89ee48/json/details/MIT.json).

Use the SPDX specification to validate expressions against the pinned list and the selected specification version. In 3.0.1, `AND` and `OR` combine expressions, `WITH` pairs a simple expression with a license exception or addition reference, and `+` has version semantics. User-defined `LicenseRef-` and `AdditionRef-` tokens require the appropriate document context. Preserve the case of published identifiers while applying the specification's case rules for matching. Keep expression syntax, document-local definitions, curated exception relationships, and the set of documents a particular project needs as distinct inputs. [SPDX 3.0.1 expression syntax](https://spdx.github.io/spdx-spec/v3.0.1/annexes/spdx-license-expressions/), [SPDX 2.3.1 expression syntax](https://spdx.github.io/spdx-spec/v2.3.1/SPDX-license-expressions/), [SPDX exception list](https://spdx.org/licenses/exceptions-index.html).

## Architecture and differentiation

Use SPDX for identity, validated expressions, exact upstream population accounting and preserved history. Use publisher sources for independently attested legal texts and edition-specific application guides. Reconcile OSI and FSF classifications with separate attribution. Use mature corpora and tools for discovery, REUSE declarations, and detection. Cataloging, file installation, clause research and publication qualification each have separate state.

Choose a License and the European Commission Licensing Assistant demonstrate concise comparisons. Licensee addresses detection. REUSE already handles file-level metadata and project checks. ScanCode demonstrates wide, versioned corpus coverage. The proposed combination is an offline-capable catalog tied to a pinned full release, source-authorized installation for an explicit subset, structured educational profiles with claim-level citations and uncertainty, and reproducible outputs carrying Software Commons evidence qualification. A comparison can use shared evidence dimensions and still display source scope, edition, condition, explicit absence, and unresolved treatment independently.

A minimum source record should bind the source authority and its role, immutable location or retrieval snapshot and digest, encoding and line endings for text, publication rights evidence, and the affected canonical identities. A release update should compare pinned upstream manifests and artifact digests, retain historical identities, and queue only dependent claims and installer recipes for revalidation.
