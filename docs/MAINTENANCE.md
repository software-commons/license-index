# Registry maintenance

The sharded candidate and entity files are authoritative registry inputs. `research/sources/` stores exact upstream revision and checksum manifests. `research/campaigns/` stores provisional review material. `registry/coverage/current.json` matches a retained snapshot byte-for-byte. Version 4 records the preceding assessment's path, Git commit and SHA-256, plus included ecosystems, discovery paths, exclusions, inaccessible areas and reconciliation choices. It retains the disposition and evidence counts from version 2 and the dimension states, scenario counts and assessment digest introduced in version 3. Earlier snapshots retain their original bytes and replay under their original formats. Exact SCES sources, claims and dispositions belong in `sces/records/`. Add permitted source bytes under `sces/artifacts/` and use `legal-texts/` for documented redistributed developer copies.

For the version 3 dimension digest, map each exact SPDX identifier to its complete `dimensions` object. Serialize as UTF-8 JSON with sorted keys, two-space indentation, unescaped Unicode and one final LF. A change to an individual dimension's state, text or citations requires a new coverage snapshot even if aggregate counts stay the same.

## Reconcile an SPDX release

1. Run `python -m tools.reconcile discover` at release adoption time to resolve the current stable tag, data commit and source XML commit. Record the archive acquisition digest. Check a publisher checksum if available and explicitly identify any locally measured transport digest.
2. Run `python -m tools.reconcile prepare-latest --output NEW_DIRECTORY` to download and stage the resolved release. Add `--sha256` to verify an independently acquired archive digest. For an existing archive use `python -m tools.reconcile prepare --archive PATH --release X.Y.Z --data-commit FULL_SHA --source-commit FULL_SHA --sha256 ARCHIVE_SHA --output NEW_DIRECTORY`.
3. Inspect the staged plan, including changes to bytes, deprecation or removal, restored entries, source locations, and impacted evidence or entity references. Reopen controlling sources for affected claims and schedule SCES revalidation. Merge only the reviewed candidate deltas through the ordinary pull-request workflow.
4. Add the exact source manifest for the new population and its immutable coverage snapshot. Keep earlier snapshots, their exact source manifests, and record histories. An unchanged SPDX entry retains its original artifact pin and opaque ID. Separate qualified review controls handle movement from discovered to canonical entities.

Run `python -m tools.index validate --spdx-archive PATH --policy PINNED_SCES_CHECKOUT --base FULL_TRUSTED_BASE`, `python -m tools.schema_check --policy PINNED_SCES_CHECKOUT --base FULL_TRUSTED_BASE`, and `python -m unittest discover -s tests -v`. Supply the retained archive for the current committed SPDX data pin and the target branch commit used to prepare the change. Schema validation and the pinned policy check use the organizational Python requirements. Normal CLI operations and the development bundle use the Python standard library.

Registry CI uses `--fetch-spdx-archive` to replay the current catalog and each incoming coverage snapshot. It checks the current release's exact public tags in `license-list-XML` and `license-list-data` against the recorded commits. For a historical snapshot it fetches the exact retained commits from those upstream repositories, since a managed tag may have moved. Each source pin is loaded once per run. The replay checks the archive size, SHA-256, and reconstructed manifest, then checks the case-sensitive inventory and artifact fingerprints for each catalog. It validates snapshots in Git ancestry order before replaying the live catalog against its last verified ancestor. With `--spdx-archive PATH`, offline validation reports `local-current` and can use incoming ancestors that match the supplied exact archive. Supply a protected base with earlier approved origins or use online replay when the required predecessors have different pins. Without either archive option, validation reports `references-only` for SPDX. Preserve the exact compressed archive for offline replay. If GitHub regenerates it with different compressed bytes, investigate and independently verify the replacement acquisition before changing the pin.

An incoming archived snapshot must be the exact current ledger when it is first recorded. Replay its assessment and sources at that commit, even if the same snapshot becomes current again. Keep every snapshot introduced in the incoming history at its recorded path with the exact archived bytes. The first foundation snapshot had a pre-integration draft that counted 94 SPDX headers. Its independent review corrected the count to 93 before integration. The two exact draft commits remain in Git, and replay uses the exact corrected archive at its first recorded cutoff. A version 4 predecessor must name the exact assessment selected by the introducing commit's first parent. Its pinned revision and digest must identify the retained archive. For an active publication, obtain the bound claim payload from `tools.qualification.qualified(catalog, policy)` before recording the assessment with `catalog.coverage(claims)`. Registry validation checks those counts against the active selection. For historical selections it reads the exact Git snapshot and applies the pinned policy at the recorded commit's time.

Registry CI also uses `--fetch-rights` to verify packaged text rights digests against the two pinned publisher documents. Each exact HTTPS URL is retrieved once per run for use across the current and incoming historical coverage records. For offline verification, supply `--rights-root PRIVATE_CUSTODY_DIRECTORY` containing the exact acquired Creative Commons README as `cc-rights-exact.md` and the PolyForm copyright statement as `polyform-rights-exact.md`. Keep these custody copies outside the distribution. Without either rights option, local validation reports `references-only` for publisher rights.

## Export development data

`python -m tools.index export` returns a deterministic JSON discovery view. `python -m tools.index bundle NEW_ZIP_PATH` builds a deterministic, extractable distribution with launchers, the development catalog, packaged texts, the current coverage snapshot, its immediate predecessor, and the source manifests for current membership and retained artifact pins. Supply `--policy PINNED_SCES_CHECKOUT` for these commands when the source checkout has an active publication. The offline bundle preserves the archived counts and identifies them as snapshot observations. The extracted bundle has no local qualification authority. Earlier snapshots remain in Git and are validated on admission. Bundle membership comes from the validated catalog and an explicit list of support files. ZIP paths, timestamps and modes are fixed, with stored entries to keep the output independent of compression implementations.

The initial SPDX snapshot is reproducible from the archive at the pinned data commit and the committed UUID allocation files. Replay reconciliation against those allocations to reproduce the no-change state. Fresh first-time allocations are deliberately random and become stable once recorded.

## Preserve provenance

Add publisher and research origins with an exact edition, date or immutable source when available. Record the difference between text bytes and display representations. Use the SCES task brief and immutable source and verification records for new factual claims. Add upheld findings with their exact revision, scope and evidence. Provisional notes remain available for research and correction.

When adding an offline publisher text, record the admitted identifiers and exact edition, acquisition digest, representation, source and redistribution evidence. Update the publisher binding used by Registry CI and the CLI for those identifiers. List any SPDX variants that share the same publisher bytes explicitly. For GNU variants that share bytes, retain each identifier's own installation guidance so an installer can distinguish version elections and notice options. Preserve previous bindings needed to replay historical snapshots.
